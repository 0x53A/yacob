# Second correctness pass — 2026-09-08

Scope: bounded bug fixes, regression tests and code review on top of the
uncommitted 2026-09-07 changes. No public application architecture redesign,
gateway changes, hardware actions, staging, commits or pushes. Existing user
changes and the simulator findings remain intact. This is a follow-up record,
not a declaration that every file or protocol is now correct.

## Fixed in this pass

1. **Empty SDO uploads decoded as four zero bytes.** The expedited encoder
   accepted an empty slice despite having only two bits for its unused-byte
   count. It now rejects empty input; the server uses a zero-length segmented
   upload. A real Node/client round trip checks that the returned length is zero.
2. **Segmented downloads ignored the declared transfer length.** The server
   now rejects overrun and short final transfers before OD commit. Explicit
   zero and unspecified size are tracked separately, including block downloads.
   Tests cover shorter/longer declarations, explicit zero, unknown size,
   valid data and absence of writes/events on failure.
3. **Server aborts could leave an older transfer alive.** An error initiating
   an upload while a download was active could abort the new request but leave
   the old download state available for later segments. A generated server
   abort now terminates that channel's transfer. Regression: old download,
   failed replacement upload, then stale download segment; nothing commits.
4. **EMCY announcements were popped before TX acceptance.** Node now peeks
   and only consumes accepted announcements, stopping the drain on refusal.
   Existing bounded queue/overflow semantics are unchanged.
5. **Periodic heartbeat refusal advanced its timer.** Node now confirms the
   periodic heartbeat timestamp after acceptance. Retry samples current NMT
   state instead of retaining an obsolete heartbeat payload. The standalone
   `HeartbeatProducer::poll` API retains its previous consume-on-poll contract.
   Initial boot-up announcement loss is not fixed by this change.
6. **Asynchronous TPDO refusal lost triggers and advanced timing.** Node uses
   a crate-private callback path that commits the existing per-PDO trigger and
   timestamp only on acceptance. Retry samples the latest OD image, not an old
   frame. Standalone `TpdoEngine::poll` still treats insertion into its caller's
   output vector as handoff. No new TX queue was added.
7. **TPDO event timers bypassed inhibit time.** Both event-timer and application
   triggers now respect inhibit time. Regression uses a 1 ms event timer and
   10 ms inhibit, including a refused transmission and latest-value retry.
8. **Malformed SLCAN DLC byte could panic in debug/overflow-checked builds.**
   The parser subtracted ASCII zero without checking underflow. It now uses
   checked subtraction. All 256 possible DLC bytes are exercised.
9. **UDP multicast metadata could change frame identity/type.** The decoder
   masked high ID bits, ignored the DLC and admitted short CAN-FD messages as
   classic frames. It now rejects out-of-range standard IDs and inconsistent
   DLC/data lengths, and filters FD alongside extended/remote/error frames.
   Tests check normal input and each invalid variant without using a network.
10. **Dynamic PDO activation accepted unusable target objects (DSIM-01).**
    Generated TPDO/RPDO mapping-count writes now check existence, subindex,
    PDO eligibility and direction/access before committing the new count.
    This applies to direct OD writes and SDO writes. Tests cover each failure,
    an unchanged zero count after refusal, and actual valid remapped TX/RX
    wire fields. Existing dummy and partial-width semantics are preserved.
    Width compatibility, zero-bit descriptors and disable-before-remap policy
    are not solved here; the downstream simulator pin/workaround is untouched.
11. **Generated fixed-width OD reads could panic on short output slices.**
    Fixed-width metadata guards short caller buffers, including generated PDO
    communication/mapping records. The usual >=8-byte buffers skip the extra
    lookup. Variable-length reads keep their existing length checks; write-only
    and missing objects retain their error precedence. Tests verify failure
    without partial output writes.
12. **Overlong NMT/heartbeat packets changed state or refreshed leases
    (DSIM-03).** Node now requires exactly two NMT bytes and one heartbeat
    byte. Regressions exercise every classic DLC from zero through eight,
    checking NMT state and consumer expiry. The concurrent simulator note
    `drive-simulator-findings-2026-09-08.md` supplied concrete reproductions;
    its pinned downstream copy remains unchanged.

The first three reproductions added before implementation (empty upload,
segmented-size mismatch and refused EMCY) failed on the preceding working
tree and pass after the fixes. Further coverage includes a deterministic
32,768-request malformed-SDO stress sequence, mixing real object addresses,
transfer commands and TX refusal. This is bounded robustness testing, not a
replacement for coverage-guided fuzzing or a conformance certification.

The size/abort handling was also cross-checked against
[CANopenNode's SDO server](https://github.com/CANopenNode/CANopenNode/blob/master/301/CO_SDOserver.c).
That implementation is a comparison point, not a substitute for a normative
CiA specification. No external code was copied.
The asynchronous PDO timer/inhibit rules were cross-checked against
[CANopenNode's PDO tutorial](https://github.com/CANopenNode/CANopenDemo/blob/master/tutorial/PDO.md).

## Remaining boundaries

- The boot heartbeat and LSS response paths still ignore transmit refusal.
- `Ok(Some(displaced_frame))` handling remains an adapter-contract problem;
  these changes establish refusal handling, not physical-delivery guarantees.
- RX drains and master pump work remain unbounded. Queue shutdown/wakeup,
  gateway stale-segment cancellation and channel reuse after client timeout
  still need the already-recorded lifecycle work.
- DSIM-02 (a heartbeat received during a delayed poll can hide an elapsed
  lease) remains open: processing-time expiry versus acquisition-time semantics
  needs an explicit contract. Exact DLC validation does not solve that ordering.
- Do not remove the simulator's application validation hook merely because
  its nonexistent-object reproduction is now fixed upstream. Its width and
  remap-state restrictions remain broader than this patch.
- No new buffering, owner/session API, application model or schema architecture
  was introduced. No human-authored DOGMA/README was created or edited.
