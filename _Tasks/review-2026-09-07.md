## Assessment and scope

The crate boundaries are useful: protocol state machines in `canopen-core`,
OD/device generation in `canopen-derive`, platform transport adapters, and
applications/tools above them. Keep that separation. The main weaknesses are
in cross-layer contracts: transport acceptance, bounded progress, lifecycle
invalidation, channel ownership, and the distinction between data and commands.
These warrant focused changes, not a rewrite justified by the age of the code.

Inspected: Node orchestration and lifecycle, SDO client/driver and server
dispatch/transfer paths, PDO acceptance and scheduling, OD events, heartbeat,
LSS integration, EDS import and client generation, DCF, shared-bus pump/queues,
SocketCAN/SLCAN/UDP/WebSocket adapters, CI and representative examples. Read the
current issue/conformance indexes and principal application/SYNC design notes.
This was a targeted architecture and correctness review, not an exhaustive
line-by-line audit of every file. Firmware-update bootloaders, canwsd server
security, browser execution and hardware timing need separate reviews/tests.
No rover, firmware flash, live CAN bus, or hardware HIL was used.

The architectural discussion is in
[architecture-review-2026-09-07.md](architecture-review-2026-09-07.md).

## Open findings and decisions

### R05 — high: protocol transmit acceptance is not reliable

Originally reproduced by refusing one SDO upload response, then restoring
capacity: no response was retried. The follow-up implementation below fixes
the Node SDO path. Other `Node::process` paths still pop EMCYs and consume
heartbeat/async TPDO work before ignoring transmit failure; R05 remains open
for those paths and transport displacement.

The older notes cover `WouldBlock` but miss the other half of the
[`embedded-can` contract](https://docs.rs/embedded-can/latest/embedded_can/nb/trait.Can.html):
`Ok(Some(frame))` returns an older frame displaced from the driver's queue.
`Node`, `NbCanAsync` and `run_pump` discard it. Even the paths using `is_ok()`
for two-phase SYNC acceptance do not account for displaced work. This matters
for adapters that implement hardware-mailbox replacement; current FIFO
adapters generally return `Ok(None)`.

Discussion: explicit no-eviction adapter contract versus retaining displaced
frames; protocol-owned pending responses versus a Node outbox; bounded full
queue behavior and scheduling fairness. Do not mistake “never silently lose
accepted protocol work” for “an arbitrarily large non-lossy queue is possible.”

### R10 — high: process/pump work and freshness are unbounded

Source-confirmed in `Node::process` and `bus::run_pump`. Node samples time once,
then drains RX until idle before servicing timers. A continuously replenished
RX stream can starve timers and return-to-application. All frames drained in
that call receive the same processing timestamp, irrespective of queue age.
The master pump likewise drains RX, then TX without a per-turn budget; while
retrying one TX it does not service RX or stop, for up to 500 ms. A continuously
fed TX queue can postpone RX/stop longer still.

Discussion: frame/time budgets, service ordering, receive timestamps, maximum
queue residence and expiry. Polling more frequently does not establish an
upper bound if a poll can itself run indefinitely. No throughput benchmark
or hardware timing claim was made here.

### R11 — high: shared-bus teardown and SDO ownership are incomplete

Existing closure/filter issues confirmed in `bus.rs`. `TxQueue::send` and
`send_async`, and subscription receives, have no closed state. Pump failure
cannot wake them with a disconnect result; `SubscriptionPort::Error` is
`Infallible`. `publish` invokes arbitrary filters and subscriber wakeups while
holding the subscriber-list mutex, inviting reentrancy deadlock and poisoned
state after a panic.

Additionally, fanout is not SDO-channel arbitration. Two independent clients
subscribed to the same server channel can both initiate transfers and receive
each other's replies. R01 detects differing initiate addresses, but segment
frames and retries to the same object cannot be disambiguated that way.

Discussion: explicit close/wake semantics, per-channel serialization, and
timeout/cancellation cleanup before reuse. Process supervision belongs to the
application; the library still needs to make its own waiters releasable.

### R12 — medium: browser transport has weaker delivery semantics

Source-confirmed in `canopen-web/src/transport/{mod,canwsd}.rs`. `send` returns
`()`, silently returns when no socket exists, and ignores JS send errors.
Its RX `VecDeque` has no capacity; browser TX buffered amount has no guard.
The native WebSocket adapter has a bounded TX queue and maximum transmit age.
The browser API cannot currently provide that same acceptance/error contract.

Discussion: a fallible send surface plus explicit queue/age policies, shared
conformance tests across native/browser adapters. Browser behavior was not
executed in this review. SLCAN's synchronous `write_all` and SocketCAN's
`recv_blocking` on an opened nonblocking socket also deserve adapter-contract
work; neither is addressed by fixing the error classifications in R06.

### R13 — medium: integrated LSS cannot complete the advertised configuration path

Source-confirmed: `Node` owns a private `LssSlave`, dispatches requests and
sends success, but neither drains nor exposes its `take_event()` events.
Configuring an ID changes the LSS object's ID, not Node's active ID or the
other protocol COB-IDs. Store Configuration is acknowledged without an
application persistence handler. Reset does not reconcile that split.
The standalone LSS state machine is useful; the integrated feature is not
equivalent to a completed commissioning path.

Discussion: make LSS opt-in with explicit configuration/store completion,
identity binding and reset integration, or advertise it as observation/partial
support. Do not infer operational correctness from standalone LSS tests.

### R14 — high for commands: OD notifications are not an ordered command stream

Known design gap, confirmed in `Node::next_change` and `OdChanges`:
events contain addresses, while typed values are read when drained. Writes
`1, 2, 3` before draining can appear as `3, 3, 3`; overflow drops events.
The same pattern appears in `vcan_node`'s command-like EMCY test handling.
The planned replacement API is not implemented.

RPDOs enforce exact payload length, but still commit mapped fields separately
through `od.write`, bypassing the SDO `validate_write` hook. A structurally
valid but application-rejected write can refresh the reception deadline.
These are different claims: wire freshness, application acceptance, and
atomic command acceptance. This review does not impose transactional command
semantics on every process-data PDO.

Discussion: separate latest-state observation from edge-preserving commands
and deferred application completion. Decide the required guarantees before
choosing inline/reactive/scan API names or deleting compatibility surfaces.

### R15 — medium: EDS/schema validation remains fragmented

Source-confirmed in `eds_parser.rs`: COB-ID values and mapping words still
narrow `u64` with `as u32`, and data types use `as u16`. Unresolvable mapping
entries can be silently omitted. Fixing a few PDO parameter conversions did
not make the import boundary generally checked. The runtime DCF fixes in R09
do not fix this separate parser.

Manual config, generated config, imported EDS and SDO writes do not share one
validator. Public engine mutation/resync can bypass the runtime guards or
preserve old phase/pending state under a new configuration. This is the
remaining reconfiguration issue in the older backlog.

Discussion: a neutral schema representation and common validation rules;
strict errors versus explicitly requested vendor-file tolerance. Generated
SDO “typed” APIs also expose `i8`/`i16` as unsigned and omit several types;
that is API completeness debt, not proof that the wire codec is wrong.

## Other backlog retained with qualifications

- Block-download sequence-gap recovery, updater post-erase retry, incomplete
  SYNC phase/payload/timeout features, additional-channel EDS import, EMCY
  `0x1003/0x1014/0x1015`, TIME, guarding and FastScan remain in the existing
  issue/conformance files. Not every omission has the same relevance to FRoST.
- Same-channel SDO collision handling cannot promise independent concurrent
  clients: generic segment frames do not identify a client or object. The
  older suggestion to preserve one transfer while rejecting another is not
  a substitute for channel ownership.
- The older updater proposal to retransmit an initiate request must account
  for duplicate side effects and late responses, not just address checking.
- `Node::set_error`'s EMCY state and the application's OD `0x1001`/`0x1003`
  remain separate. `ResetType::Application` does not itself restore all OD
  application defaults. These advertised ownership boundaries need clearer
  documentation or APIs; not silently chosen policy in this patch.

### Follow-up: narrow SDO backpressure patch

Implemented the SocketCAN/SDO first slice after discussion with Lukas, without
changing the public Node API or the gateway worker/queue architecture:

- SocketCAN maps `ENOBUFS`, as well as `WouldBlock`, to retryable backpressure.
  Interface-down/removal and other errors remain `BusError`.
- Each Node SDO channel has one pending response slot. Ordinary responses,
  timeout aborts and block-upload segments use it. Failed transmission keeps
  the frame; no further ordinary request on that channel is processed while
  it is pending. Other channels remain independent.
- A refused frame is attempted at most once per Node poll. Block generation
  stops on refusal and emits at most one sub-block per service call. This does
  not fix R10's unbounded RX drain.
- Local/NMT resets and client aborts discard pending work. Pending responses
  expire after the existing five-second SDO timeout, including expedited
  replies without an active segmented transfer. Expiry is checked before RX
  dispatch; retries occur after RX so a queued reset can cancel old work.
- Writes are not repeated on retry, and committed OD changes are not rolled
  back when their acknowledgement cannot be delivered. Only library-owned
  frames can be discarded; downstream queues are outside this guarantee.
- Other transport errors also retain the response until expiry/reset because
  Node's current void processing API has no error-return channel. Hardware
  displacement (`Ok(Some(frame))`) remains unresolved, as in existing paths;
  this patch establishes refusal handling, not a universal delivery guarantee.

Regression coverage includes acceptance exactly once, bounded retry,
write-once semantics, expiry, local and NMT resets, client abort, independent
additional channels, synchronous RPDO progress, timeout-abort retry and block
segment order. Heartbeat/EMCY/async TPDO acceptance and gateway stale-segment
cancellation are still follow-up work, not claimed fixed here.
